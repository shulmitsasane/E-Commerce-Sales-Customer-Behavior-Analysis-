# E-commerce Sales & Customer Behavior Analysis

## Overview

This project analyzes e-commerce transaction data to understand customer behavior, purchasing patterns, revenue performance, and customer retention.

The project is designed to support:

- Exploratory Data Analysis (EDA)
- RFM customer segmentation
- Customer churn prediction
- Logistic Regression and Random Forest modeling
- Identification of major churn indicators
- Revenue and customer value analysis

The original dataset contains more than 500,000 transactions. After cleaning cancelled transactions, invalid values, duplicate records, and missing customer information, approximately 392,000 valid transactions remain for analysis.

## Dataset

The project uses the UCI Online Retail dataset, containing transaction-level data such as:

- Invoice number
- Product code
- Product description
- Quantity
- Invoice date
- Unit price
- Customer ID
- Country

## Data Cleaning

The following preprocessing steps were performed using Python and pandas:

- Removed duplicate records
- Removed transactions with missing customer IDs
- Removed records with missing product descriptions
- Removed cancelled transactions
- Removed negative or zero quantities
- Removed negative or zero unit prices
- Converted customer IDs to integer format
- Created a Revenue field using:

`Revenue = Quantity × UnitPrice`

After cleaning:

- Original transactions: 541,909
- Cleaned transactions: 392,692
- Missing values in cleaned data: 0

## Exploratory Data Analysis

EDA is performed on the full cleaned transaction dataset to analyze:

- Total revenue
- Number of unique customers
- Number of unique products
- Revenue by country
- Best-selling products
- Highest-value customers
- Customer purchase frequency
- Revenue distribution
- Quantity distribution

### Outlier Review

Transaction-level quantity and revenue distributions were highly skewed. 
The largest transactions were manually reviewed and found to have internally
consistent quantities, unit prices, and revenue values, suggesting legitimate
high-volume purchases rather than obvious data-entry errors.

Extreme values were retained for business and revenue analysis. For predictive
modeling, skewed monetary features are handled through appropriate feature
transformation to reduce the influence of unusually large transactions.

## RFM Analysis

Customer-level purchasing behavior was summarized using the RFM framework:

- **Recency:** Number of days since the customer's most recent purchase
- **Frequency:** Number of unique orders placed by the customer
- **Monetary:** Total revenue generated by the customer

The transaction-level dataset was aggregated into one record per customer, creating the customer-level dataset used for segmentation and later churn modeling.

## Customer Segmentation

RFM scores were converted into customer segments based on recency,
purchase frequency, and monetary value.

The main customer groups include:

- Champions
- Loyal Customers
- Recent Customers
- At Risk
- Lost Customers
- Needs Attention

This segmentation helps identify valuable customers, retention opportunities,
and customers showing signs of disengagement.

## Churn Definition and Feature Engineering

To create a churn prediction problem, the transaction history was divided
into an observation period and a future prediction period.

Customer behavior before September 1, 2011 was used to generate model
features, while transactions from September onward were used to determine
whether customers returned.

A customer was classified as:

- **Churn = 0:** Customer made another purchase during the future period
- **Churn = 1:** Customer did not make another purchase during the future period

Features created for modeling included:

- Recency
- Purchase frequency
- Monetary value
- Total quantity purchased
- Number of unique products purchased
- Customer tenure
- Average order value
- Average quantity per order

This time-based approach helps prevent data leakage by ensuring that future
purchasing behavior is not used when constructing predictive features.

## Churn Dataset

A time-based churn dataset was created using September 1, 2011 as the cutoff date.

Customer behavior before the cutoff was used to generate predictive features,
while transactions after the cutoff were used to determine whether each
customer returned.

The final modeling dataset contained 3,317 customers.

Churn distribution:

- Not churned: 58.85%
- Churned: 41.15%

The relatively balanced target distribution allowed the models to be trained
without synthetic oversampling.

## Advanced Feature Engineering

Additional behavioral features were engineered to capture changes in recent
customer activity:

- Orders in the previous 30 days
- Revenue in the previous 30 days
- Orders in the previous 60 days
- Revenue in the previous 60 days
- Orders in the previous 90 days
- Revenue in the previous 90 days
- Number of active purchasing months
- Average number of days between orders

These features were added because lifetime metrics alone may not capture
recent changes in customer engagement. For example, two customers may have
the same historical purchase frequency while having very different recent
purchase behavior.

## Threshold Tuning

The Logistic Regression decision threshold was evaluated across several values
to balance precision and recall.

A threshold of 0.40 produced the strongest F1-score:

- Accuracy: 64.5%
- Precision: 54.1%
- Recall: 88.6%
- F1-score: 67.2%

This threshold was preferred for churn detection because it substantially
improved recall, allowing the model to identify a larger share of customers
who actually churned.

## Model Comparison

Three classification approaches were evaluated using the same 80/20
train-test split.

| Model | Accuracy | Churn Precision | Churn Recall | Churn F1 |
| --- | --- | --- | --- | --- |
| Logistic Regression | 66.3% | 56.4% | 79.5% | 66.0% |
| Logistic Regression (0.40 threshold) | 64.5% | 54.1% | 88.6% | 67.2% |
| Random Forest | 65.2% | 56.0% | 73.0% | 63.0% |
| Gradient Boosting | 67.6% | 59.9% | 64.1% | 62.0% |

Gradient Boosting achieved the highest overall accuracy, while threshold-tuned
Logistic Regression achieved the highest churn recall.

### Key Churn Indicators

Gradient Boosting feature importance highlighted the following customer
behavior signals:

1. Active purchasing months
2. Number of unique products purchased
3. Average order value
4. Revenue generated in the previous 90 days
5. Total quantity purchased

## Revenue and Customer Value Analysis

Business-level metrics were created for dashboard reporting, including:

- Monthly revenue
- Monthly order volume
- Active customers
- Average order value
- Product revenue and quantity sold
- Customer-level historical lifetime value

A historical CLV proxy was calculated using customer order value,
purchase frequency, and observed customer lifespan.

Because the source dataset does not contain website sessions or product-view
data, true conversion rates cannot be calculated directly. Product purchase
and revenue performance are therefore used for product-level analysis.
